# 研究模型基线

本文记录受控通道的业务流程、数学模型及实现选择。采集与独立评分按[通道资料规格](../experiments/corridor-data-spec.md)准备，设计交付和待做任务统一见[研究任务计划](../ROADMAP.md)。[现行方法与备选](#method-options)给出采用条件。

## 从地图准备到持续运行的完整流程

本节按首轮受控通道串接现行设计。建图、定位和导航由用户负责，研究侧实现输入关联、状态、验证义务、MSRP、验收与用途判断。语义分割工具已有公开实现候选，校园数据上的分割、人工校验和地图接入仍待完成。

| 步骤 | 输入及处理 | 可复用工具及需要编写的逻辑 | 产出与责任 |
| --- | --- | --- | --- |
| 1. 建立地图 | FAST-LIO2 点云及位姿，处理点云或同步图像的语义候选，校验时空信息及覆盖。 | FAST-LIO2；按数据选择 Open3D-ML，或 Grounding DINO/SAM 图像分割及三维投影。模型、数据转换、标定和融合需要匹配与试跑。 | 用户提供几何和定位；S2 接入地图及语义候选。 |
| 2. 校验实体与关系 | 人工复核关键分割、校园名称、入口/出口、楼层和重要关系。 | CloudCompare 提供点云查看、人工分割及测距；Python UUID 生成新实体编号，SQLite 保存身份及别名，Shapely/NetworkX 计算几何关系及保存图；人确认对象和关键关联。 | S2 提交地图、关联、分区和关系图修订。 |
| 3. 定义可验收要求 | 登记净宽等功能要求、范围、证据模板及窗口，机器人 Profile、有限动作、允许终点和成本。 | JSON 配置、jsonschema 结构与参数检查、SQLite 版本索引。研究者定义要求、证据语义及未知处理，程序读取配置。 | S4 引用要求及模板，S5/S6 取得动作及能力输入。 |
| 4. 接入记录及首次观测 | S1 接入维修、许可、人工报告及观测，保留原件、来源和双时间；S2 解析地点。 | Python csv/json 读取业务表，jsonschema 校验，名称/ID 索引与 Shapely STRtree 精确空间查询；MCAP/Rosbags 读取观测。需编写来源和字段适配。 | 合格输入进入 S3/S4，歧义保留候选。首次观测也经同一验收链。 |
| 5. 形成复核需求 | 接收维修完成、异常线索、证据失效、地图更正或定时请求，分析功能影响。 | NetworkX 图遍历、Python 触发与属性映射规则、SQLite 事务。需实现 APCM、类型化闭包、义务模板实例化及去重。 | S4 登记/关联事件，产生范围、要求、截止和证据明确的义务。 |
| 6. 核对旧证据及缺口 | 在当前地图、用途及预计验收时间下核验覆盖、误差、时效、来源和联合分配。 | Shapely covers/intersection、时间区间检查、OR-Tools 见证分配。研究代码实现 D02/D07/D08 的资格及共因约束。 | 充分时直接验收；其余缺口交 S5。 |
| 7. 规划完整作业 | 联合选择完整路线与见证，检查安全、时窗及资源。 | OR-Tools CP-SAT 求解布尔/整数约束，NetworkX 提供图路径计算。需编码 MSRP 的完整路线、资格两套视图、成本及多轮策略。 | S5 输出计划或 INFEASIBLE/UNKNOWN 及依据，S4 受理为 Task。 |
| 8. 实际采证 | 用户平台执行导航、观测及安全结束，回传实得数据与成本。 | 调用用户导航/观测接口；MCAP/rosbag2 保存消息。需适配目标、地图修订、时窗、许可、采集和结束回执，具体接口按平台代码确定。 | S3 整理实得证据，失败或失联等缺口及实耗照记。 |
| 9. 验收与状态更新 | S4 按原要求判断 PASS、FAIL 或未决，S3 应用有效结果。 | jsonschema 检查结构，Shapely/数值与时间计算核验资格和内容，SQLite 事务更新状态。需实现独立验收器及恢复重开规则。 | 结果供用途查询；未决按剩余机会和新信息决定后续处置。 |
| 10. 任务使用与重评 | S7 结合许可、机器人、路径和整个时窗检查，S6 消费有效约束。 | Python 条件规则、Shapely 路径/区域运算、SQLite 一致读取，再接用户导航接口。需实现五态证明、版本失效和反馈触发。 | 用途结果及理由；新事实或周期请求再次进入相应步骤。 |

S8 为各步保存原始制品、策略与标定修订、摘要及审计关联。S7 也在第 7–8 步为复核作业用途提供约束。流程中的先后描述表示业务依赖，运行时各模块可多次交互。完整模型分别见下文 R1–R3、[D06](observation-bootstrap.md)、[MSRP](msrp-model.md)及[资料规格](../experiments/corridor-data-spec.md#management-inputs)。

基础库的来源、许可、安装版本及本机调用范围集中维护在[工具复用核验](../experiments/readiness.md#tool-reuse)，机器人主机、Thor 和工作站的环境及交接见[平台分工](../experiments/readiness.md#platform-layout)。

### 第 3–10 步的限定串联检查

在本机以固定合成通道、给定几何/时间/质量/独立性条件和三条声明路线进行组件串联。流程读取 JSON 要求与 CSV 工单，经过 jsonschema、STRtree、NetworkX、CP-SAT，再消费预置采集回执、验收和 SQLite 状态读取。8 个结果均与预期一致。

| 场景 | 规划及后续结果 |
| --- | --- |
| 合格补证 | 选择侧站完整路线，取得两份完整独立达标见证，PASS，用途查询可用 |
| 实得区间跨阈值 | 路线完成，实际内容仍不足，验收未决，用途待定 |
| 实得来源重复 | 新记录与旧见证同源，验收未决 |
| 实得覆盖不完整 | 仍缺全段第二份见证，验收未决 |
| 实得证据已过期 | 新资料无法填槽，验收未决 |
| 普通通行禁止 | 复核另有适用许可，采证与物理验收 PASS，普通通行查询仍禁止 |
| 旧证据已充分 | 直接验收，派工数为零 |
| 两条采集路线安全资格均未知 | 规划 UNKNOWN，派工数为零 |

本检查支持基础组件可以沿同一记录链衔接，覆盖固定要求下的部分规则。采集使用预置回执；现场误差、保持、独立性和可执行性作为给定条件。完整 D01、APCM、MSRP、多轮流程、五态查询及真实平台仍需完整实现和验证。语义模型也仍处于候选阶段，校园推理精度及与现有环境的兼容性待试。

### 维修记录与许可怎样进入地图和义务

两类输入可先在 Excel、CSV、数据库或现有管理接口中表达，再由 S1 适配到现行接入记录。地点可以由稳定编号、校园名称别名、坐标或区域给出。业务展示编号 C001 仅用于示例，底层身份和精确修订继续按既有契约引用。

| 业务表 | 一条记录需要表达什么 | 进入系统后的用途 |
| --- | --- | --- |
| 维修/作业事实 | 工单号与记录修订；所关联实体/位置及本次作业范围；作业种类、报告状态和内容；实际发生或完成时刻；系统接收时刻；报告来源、人员及来源原件。提供测量时另附测量来源和原始资料。 | S1 保存可追溯的来源事实，S2 解析作用域，S4 按触发规则登记/关联事件并生成相应义务。工单办结后，原要求依实得证据重新验收。 |
| 许可/限制指令 | 指令号与修订；实体/区域；用途及适用对象；PERMITTED、PROHIBITED、RESTRICTED、MAINTENANCE 等管理值；生效与结束时刻；结构化条件；发出者与授权依据；系统接收时刻；替代或撤销的旧指令。 | S3 按权限、作用域、有效时间和替代/撤销关系解析管理状态。S5/S6/S7 按实际用途消费许可与限制。 |

原始表中的地点名经已确认别名关联到实体，再解析其当前版本几何。记录已有坐标/范围时，可通过 R-tree 查候选、再按楼层/高度与精确几何确认。多个候选保留歧义，缺少关联时登记为待定位。工单只涉及通道一端时，保存该端的实际作业范围，S4 再依据功能要求判断复核是否涉及整段。上述业务列说明输入含义，正式接入继续使用 S1 Intake Envelope、ManagementDirective 与既有事实类型。

## 空间身份与版本

空间实体以稳定身份关联几何、局部单元、功能与关系图。一次判定固定相关地图、关系图、变换、功能要求及策略版本。地图发布版本和动态状态修订分别维护。单元分割、合并或重投影后，按新作用域重查旧证据的覆盖、配准误差、时效与适用性。

[D10 地图消费实例](map-consumption.md) 将该基础落实到同一通道：不确定变换下，可能占用取外覆盖，保证已观察范围取交集；先保留完整原作业，再裁剪到新分区。谱系比例不作证据权重，精确重表达可重用测量，配准更正导致的真实支持缺口需要新依据。S4/S7 必须按新上下文重评，不复制旧 PASS 或允许。

## 观测入口与无告警发现（D06）

首轮采用事前授权的固定周期核验底线，以及可见线索触发的提前复核。计划时点由 S4 按行政核验请求登记业务 Event，再沿原有义务、ReviewPlan、Task 链路采证；请求本身不证明现场异常。周期与相位不随隐藏真值起点重置，请求重放不重复派工。

观测路线只使用具有独立依据的有限保护区/观察站，安全证明不得引用本轮待产证据；观测准入和运输用途分开。可执行性、观测覆盖及联合槽位资格均已证时才支持采证可行。安全侧不可见且必须穿越未知区时保留 UNKNOWN 与外部复核条件，不由取不到证据推出物理 BLOCKED。详见 [D06 模型、三条场景及十一项边界](observation-bootstrap.md)。

## R1 双源状态维护（APCM）

管理状态 $M$ 由适用的授权记录支持。物理信念 $b(X)$ 根据现场观测以及适用的转移与观测模型更新。两者通过空间身份、版本和有效时间关联。管理开放而阻塞证据充分时产生差异候选。管理封闭而现场畅通时保留禁令。遮挡、未探测范围和未知的来源关联保留不确定性。

[E1 双源维护实验](../experiments/dual-source-e1.md)首轮选用区间估计与硬过期，固定诊断范围、世界双轴真值及知识切点，独立评价物理冲突和管理冲突。S3 的合格物理断言与 E1 的 O/N/A 诊断均不代替 D02 的正式证据槽验收或 S7 的任务可用性。

[D07 时空支持模型](spatiotemporal-support.md) 选定有限几何内/外包络与受控保持区间。未知体积进入可能占用集合，按几何边界分段核查净宽，不由断面样本插值填空。采样时间误差、物理状态支持及证据使用资格分别判断；只有保持依据和当前用途都支持完整目标域时，才能组合连续或未来结论。开放环境无保持依据时保留未知，正式双槽验收及任务放行仍各查其余门禁。

[D08 联合可靠性](joint-evidence-guarantee.md) 采用有界误差的确定性集合推导，保留共享标定/变换等依赖；每份见证仍须有自身完整支撑，不能用两个区间交集伪造两独立槽。统计材料只按其实际目标与有效的有限同时保证接入，证据覆盖失败、任务风险及实验效应预算分别核验。重复查看、补测和义务重开不自动带来置信收益或预算重置。

## R2 事件、验证义务与复核规划

事件影响分析与验证义务生成（MET）从事件几何与属性定位复核种子。在固定版本和有效时间段内，对空间属性目标及功能要求目标求有类型依赖关系的闭包，空间边和多跳功能边均遍历至稳定。边方向为依赖项到依赖者，每一步显式映射属性/要求。只用确定种子和确定关系得到确认范围；加入有依据的未决种子和关系得到可能范围，两者之差为候选范围。输入清单不完整时，未到达目标不能据此排除。

确认的是“给定事件输入下的复核相关性”，功能是否满足要求由证据验收确定。AND/OR/K-of-N 的任一依赖变化可使父要求重评，不能直接推断失败。S2 只读计算，S4 登记结果并按要求模板生成或重评义务；地图/关联变化时重新锚定。详见 [D01 数学定义、伪代码与十一类纸面案例](impact-closure.md)。

验证义务固定空间单元、功能、待核验属性、有效时间、要求版本及通过谓词。首轮选择通道净宽和 `2-of-3` 模板。两份来源独立的达标见证须各自覆盖目标空间和时间。两份独立失败见证须支持同一处适用的净宽反例。`ALL`、`ANY` 和 `K_OF_N` 按不同槽计数，每槽见证数、共同原因额度与时效由冻结模板及策略定义。S4 分别记录证据提交和业务结果。足量合格反证可得到 `ACCEPTED / FAIL`，缺证和实质冲突保留未决。详见[通道净宽的证据设计与纸面复核](corridor-evidence.md)。

最小充分复核规划（Minimum Sufficient Reinspection Planning，MSRP）在固定动作目录、有限位置和离散时间生成的完整路线域中，核验权限、安全、时窗、预算和联合见证分配。移动、等待、采样及结束路段均计入成本，已有证据在预计验收时重新核查。首轮按指定范围和质量规划采证，实际读数随后由 S4 验收。完整定义及伪代码见 [MSRP 数学模型](msrp-model.md)。

| 结果 | 判据 |
| --- | --- |
| `FEASIBLE` | 至少一条完整路线满足所有采证及硬约束，并有联合见证分配。候选或成本比较未闭合时注明最优性待证。 |
| `INFEASIBLE` | 声明域及资格上界有完整性依据，所有仍可能满足条件的路线均已被排除，或有同等覆盖的无解证明。 |
| `UNKNOWN` | 尚无已证可行路线，仍有未排除候选或候选覆盖、产证资格、安全及独立性缺口。 |

成本按完整总时长、总能耗、稳定候选 ID 依次比较。要在声明生成域中证明最优，需处理全部可能更优的候选，或对遗漏部分提供有效成本下界。这是单轮合格采证的最优性，不推出多轮首次正确确认最优；下一轮行动/等待按 [D09 多轮复核策略](multiround-review-policy.md) 固定的规则选择。已有八个纸面案例已补齐前提，新增十二个边界，见 [MSRP 二十例](../validation/msrp-cases.md)。

执行后用实际证据重做验收。局部恢复按单元与功能登记。过期、新反证、证据撤销或关键版本变化触发适用性重评。受影响的旧谓词结论失去充分支撑时，S4 按策略追加重评或重开修订，S7 核查投影已应用必要变更并覆盖预计占用时段。

[E4 恢复与重开设计](../experiments/recovery-e4.md)明确：局部恢复使用预先登记的子域义务；替代见证仍充分时可重评后保持通过，只有当前持续验证失去必要支撑等情形才重开。Requirement 替代生成新的义务身份，历史修订保留原结论；有效关闭后的新 occurrence 与关闭依据失效分流为复发或重开。已有完整合格证据可直接由 S4 验收，不以新 Task 执行为前置条件。

D09 先重评新到资料，保持一次一条在途路线；在合格完整采证和已有完整供给等待之间，按最晚验收资料时点、增量能耗上界和稳定 ID 排序。无完整候选才等待有据前提或保留被动唤醒。实质签名、原截止、派发次数及已耗账防止无效重试；该保守排序不同于 D03 单轮路线成本，不声称首次正确确认或全程能耗最优。

## R3 任务条件下的空间可用性

读取机器人无关的功能状态投影，然后结合当前管理许可、能力配置、任务、路径和预计占用时窗判断。关键依据的适用区间须覆盖相关使用时窗。任务硬谓词与证据/读取/投影资格分别判断：证明失效阻止允许，不能单凭失效推出通道受阻。禁止、受阻、待复核、条件可用、可用分别表达不同依据。附加条件必须可以执行，软代价用于比较已满足硬约束的方案。区域聚合的 `PARTIAL` 保留在区域层级。

[E5 条件可用性设计](../experiments/availability-e5.md)进一步固定原请求的允许执行域。基准通过为 AVAILABLE；请求允许且全范围已核验、可执行的附加约束可支持 CONDITIONAL。否定整个请求需要全域管理禁止、共同硬反证或完整候选排除；仅某个方案失败不否定其他合法方案。只有风险上界超过预算时保持待定，有可信下界证明所有方案的风险硬条件失败才可按任务硬失败处理，原因与物理障碍分开。正向许可必须有当前读取、原裁决关联、S4 应用和完整时窗证明。

| 方案及定位 | 决策方法与可复用实现 | 预期价值及新增工作 | 适用条件与局限 |
| --- | --- | --- | --- |
| **A · 现行主线：有限域联合约束规划** | D01/D02/D07/D08 作统一基础，D03 联合选完整路线及见证；独立有限枚举作小域参照，候选实现采用 OR-Tools CP-SAT，跨轮沿用 D09。 | 便于解释充分性、无解边界及域内最优性，最贴合现有研究模型。完整参考实现和等价编码仍需完成，工作量中等。 | 适合首轮有限观测位和有界作业。候选数可能增长；整数化需保守处理窗口和预算。OPTIMAL 仅针对已编码模型，业务无解还需候选上界完整。[CP-SAT 官方说明](https://developers.google.com/optimization/cp/cp_solver) |

C 首先在与 A/B 相同的有限候选目录内检查语义一致性，再另做扩大候选域的实验；后者的改进不能全部归因于规划器。D 先在相同安全/证据资格和完整作业目录内评估；若要选择只能补齐部分前提的诊断动作，须先定义对应任务合同和评价范围，不能沿用 D09 规则声称已经支持。
