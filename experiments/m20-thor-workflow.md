# M20 Pro 与 Thor 的首轮实验步骤

更新于 2026-11-27。首轮研究一条受控直通道的净宽、一个义务修订及一个 M20 Pro 配置。本文是部署与实验计划，软件安装、算法适配和现场效果按各步独立验收。[当前任务](../ROADMAP.md) · [输入和独立参考](corridor-data-spec.md) · [实验协议](protocol.md)

## 1. 当前基础与主机分工

已通过只读 SSH 识别 Thor、AOS、NOS、GOS。M20 三台主机为 RK3588/ARM64、Ubuntu 20.04、厂商 ROS 2 Foxy 环境；Thor 为 T4000、Ubuntu 24.04/JetPack 7.2 系列，宿主未发现已安装 ROS。具体设备记录留在 [Notion 平台笔记](https://app.notion.com/p/41280c1f022081068737f619a3e65c32)，公开仓库不存连接地址、账号或凭据。

Thor 有线接口问题由用户后续处理，当前采用无线。本文将所需网络连通作为实施前提，暂不安排内网路由处理；这一假设不证明 DDS 发现、话题传输、持续带宽或时间同步已通过。

| 主机 | 首轮职责 | 实现状态与边界 |
| --- | --- | --- |
| AOS | 保留原有运动、设备和传感器服务，提供现有视频及可用观测 | 已见相机、雷达与里程计相关服务；不把“服务运行”记作数据或运动验收。 |
| NOS | 提供现有定位导航能力，后续接用户导航代码 | 实际目标接口、地图格式、坐标、取消及终态回执待对接。 |
| GOS | Foxy 侧录包、短时缓存和后续任务适配 | rosbag2 录制与任务适配程序尚待验证；不要求在此运行全部研究算法。 |
| Thor | 数据归档、离线建图、几何处理、义务、MSRP、验收及状态查询 | 首轮优先 CPU 处理；建图容器及研究环境待安装验证，GPU 模型按需求另验。 |
| 现有电脑 | CloudCompare 人工复核、编号与结果审阅 | 不以新增外部工作站为前置条件；现有工作站可承担不兼容组件的离线处理，须记录实际环境。 |

## 2. 按输入、算法和产物执行

### 第一步：GOS 录制原始观测，Thor 保存视频

用户选择一条可控制障碍和出入的短通道，事先核验观察位与到达、结束路线。建议先取得静止约 2 分钟、遥控缓行约 5 分钟的预实验记录；时长只用于首次调通，不是正式样本量。

GOS 使用实际 Foxy 环境的 rosbag2 录制雷达、IMU，以及可取得的位姿、TF 和状态。厂家配置中的 `/LIDAR/POINTS`、`/IMU` 是核对入口，须记录真实消息类型、字段、单位、frame_id、QoS、频率及每点时间。Thor 使用 FFmpeg 接收并保存 RTSP 视频，保留 PTS 和接收时间；曝光时刻未查明时，不把接收时间当作采样时间。

**交付给第二步：** 原始录包、视频、采集作业编号、配置与消息定义、时间和来源清单。先核对数据可完整读回、时间有序及缺包/断流，再扩大采集。原件保留，派生文件引用同一作业。[rosbag2](https://github.com/ros2/rosbag2) · [Rosbags](https://ternaris.gitlab.io/rosbags/)

### 第二步：Thor 用 Lightning-LM 离线建图

首选验证云深处适配版 Lightning-LM。拟在 Thor 上采用独立 Ubuntu 22.04 + ROS 2 Humble 容器，先验证 CPU、无图形界面的短包运行。厂家仓库说明支持该发行版与 ARM，并提供 M20 配置；这不等于已经验证 Thor 容器。

输入第一步的雷达与 IMU，按实机检查时间基准、每点时间、外参和单位，保存实际提交及配置。输出点云地图、轨迹和坐标说明。若已有合格的 FAST-LIO2 成果，可沿用同一输入交接规范；首轮冻结一个几何基线，不把 SLAM 性能比较并入本研究。[厂家源码及录包建图入口](https://github.com/DeepRoboticsLab/lightning-lm-deep-robotics)

**交付给第三步：** 可重复生成的几何地图和轨迹，以及独立尺寸/控制点检查。重复回放一致不能单独证明几何准确。

### 第三步：Thor 几何分割，电脑复核，形成地图版本

Thor 用 Open3D 的平面拟合、聚类和距离处理辅助产生墙面、地面与障碍候选。电脑用 CloudCompare 修正边界和分区。人工确认通道名称、Cell、实体、入口出口及功能关系，Python/SQLite 整理稳定身份与版本。

- **MapRelease M0：** 几何、Cell/实体目录、坐标单位、覆盖、来源及质量。
- **GraphRelease G0：** Cell 归属及空间/功能依赖，精确引用兼容的 M0；它不等同于 SLAM 位姿图。
- **Transform T0：** 传感器、机身、建图和导航坐标之间的适用变换、误差、来源及时间。

三者是不同对象，不是连续建三次地图。指定净宽要求、测量高度带、原目标域、保持窗口与 M20 配置。研究图与 NOS 导航图须有经核验的坐标关系，不能直接互用目标坐标。[Open3D](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud.html) · [CloudCompare](https://www.cloudcompare.org/doc/wiki/index.php/Interactive_Segmentation_Tool)

**交付给第四、五步：** M0/G0/T0、要求与证据模板、有限观察位，以及独立测量和受控保持依据。RGB 语义分割是后续辅助；当前普通视频不直接提供有尺度保证的净宽。

### 第四步：Thor 用 Open3D 处理变化和净宽

用户布置可控障碍，M20 从既有安全观察位重新采集。Thor 将新观测变换至 M0，检查稳定结构上的配准，再计算新增占用和变化候选，关联 Cell。按指定高度带与目标域生成净宽区间、可支持范围、遮挡和未知区域。

Open3D 提供几何运算；净宽定义、误差传播、完整覆盖和变化候选转换由研究程序实现。无回波不能直接视为空闲，过滤与采样不能删掉需要检出的窄障碍。经验最大残差不能自动充当绝对误差界。

**交付给第五步：** 有来源、时空范围和版本的观测及差异候选，而非直接宣布功能异常。[净宽证据](../design/corridor-evidence.md) · [时空支持](../design/spatiotemporal-support.md)

### 第五步：Thor 用类型化图遍历和模板生成义务

NetworkX 保存并遍历 G0，研究规则实现 D01 的确定/可能影响闭包、原因路径和缺关系处理。S4 按规则登记事件并实例化义务，保存原要求、范围、期限及证据槽。维修和许可先用带原件、实体/范围、生效及可见时间的 CSV/JSON 接入。

例如 C02 出现新增占用，规则分析其净宽及关联通道功能。局部观测不擅自缩小原通道义务，未知关系保留在候选范围。先验收已有资料，旧证据充分时无需新派采集。

**交付给第六步：** 义务修订、已合格证据、缺口、可用来源和候选动作。[影响模型](../design/impact-closure.md) · [业务输入](../design/model-baseline.md#management-inputs)

### 第六步：Thor 用 CP-SAT 生成完整复核计划

先登记观察位 P1/P2 等有限候选、可达路线、等待、采样配置、结束位置、产证条件及时间/资源边界。OR-Tools CP-SAT 求解研究程序编码的完整路线和联合见证约束；按 D03 的时长、能耗、稳定 ID 顺序比较。完整成本贪心共用同一资格和验收器，小域独立枚举核对编码与最优性范围。[CP-SAT](https://developers.google.com/optimization/cp/cp_solver)

当前模板为两个独立合格槽支持同一结论。同一雷达多次/多视角采集可补覆盖，不自动增独立见证；普通 RGB 视频不能直接替代独立净宽测量。首轮可评估雷达与独立人工测量作业的组合，核查共同误差并计入外部人时及到达时间。只有一份合格见证时保留未决，不能临时放宽模板。

**交付给第七步：** 带版本、观察目标、采集配置、期限和安全结束的 ReviewPlan。S4 受理为 Task 后交 S6，求解器可行不等于已派发。[MSRP](../design/msrp-model.md) · [多轮规则](../design/multiround-review-policy.md)

### 第七步：GOS 交接任务，NOS/AOS 执行并返回原始资料

GOS 的适配程序把经过 S4/S6 核验的任务交给用户提供的导航接口。NOS 承担经验证的定位导航，AOS 保留本体运动与保护。记录接收、到达、采样、结束、取消、失联及实际耗费。该目标接口和坐标交接尚未实现验收。

首轮可由用户遥控按计划到站采集，明确标记人工执行并计成本。自动任务须另核验控制权、停止/取消和本地安全，不由研究算法直接控制关节。

**交付给第八步：** 实际原始数据、作业及任务身份、版本、时间、实际范围、结束回执和实耗。执行完成不能替代证据验收。

### 第八步：Thor 验收、更新状态并重评用途

S3 按第四步整理实际证据，S4 依据原要求核验对象、覆盖、误差、时间、独立性和冲突，形成 PASS、FAIL 或未决。S3 应用裁决更新状态，S7 再结合管理许可、机器人配置、允许路径和完整占用时窗判断用途；证据缺失保留待定。新事实使原依据失效时重评，缺口返回 MSRP，沿用原截止与资源账。

**交付：** 一次可重放的“观测—事件—义务—计划—采集—验收—状态/用途”记录。SQLite 和本地制品目录即可支撑首轮逻辑原型，八项逻辑职责不要求拆成八个服务。

## 3. 跑通之后的实验顺序

先做障碍增加/移除、局部遮挡和许可变化，再加入纯分区拆分、坐标重表达及变换误差更正。每次临时障碍变化不必自动发布新基础地图；地图挑战按 D10 对同一原目标重锚定，保留合法旧证据并补缺，派生地图不增加独立样本数。

E2 比较同一事件下的影响范围，E3 比较同一义务和动作域下 MSRP、完整成本贪心及全域复核。E1/E4/E5 分别核验双源、恢复和用途。总体按相同周期底线与可见信息规则比较提前复核和固定周期巡检，记录无初始告警、无变化、失败及未决。回放不能免费提供某方法未执行动作的观测，也不能把隐藏真值作为触发线索。

用于验收的人工测量与用于评分的独立参考分开登记。先分独立组，再派生帧和更正版本；正式样本量由预实验估计，不能用重复帧充数。主指标为确认时间与验证成本，同时核查漏检、正确确认和危险误放行。原始现场数据按其授权位置保存，不随设计文档自动公开。
